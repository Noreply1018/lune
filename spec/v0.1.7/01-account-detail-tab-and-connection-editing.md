# 01. 账号详情抽屉 tab 与直连连接信息编辑

状态：release-ready。实现和验收已经纳入 v0.1.7 发布阻塞矩阵；最终 `gpt-5.5` subagent 严格审计已通过。

来源：来自账号详情抽屉的直接体验问题。当前详情抽屉的 tab 中夹杂中文 `诊断`，和前面的英文 tab 不一致；同时直连账号缺少一个合适的位置来编辑 API 地址与 token，导致连接变更必须依赖更重的入口或外部配置。

## 问题

- 详情抽屉的 tab 语言不一致，`Overview / Playground / 诊断` 在视觉和语义上都不统一。
- 直连账号的 API 地址和 token 是核心配置，但当前没有内聚的编辑区，用户只能在更外层页面或创建流程里处理。
- 连接信息若放到诊断页，会把“排障”和“配置”混在一起，使用心智不清晰。
- token 如果以空输入框直接出现，用户容易误判为丢失；如果强行展示完整明文，则暴露面过大。

## 改进策略

- 账号详情抽屉的 tab 统一使用英文：`Overview / Playground / Diagnostics`。
- 直连账号的连接编辑区放在 `Overview` 顶部，位于 route 摘要之后、指标和模型信息之前。
- 连接编辑区只对 `openai_compat` 账号显示，CPA 账号不显示。
- 连接编辑区分为两部分：
  - 当前状态：显示 masked token 或 `Token missing`。
  - 编辑区：`API Base URL` 输入框和 `API Token` 输入框。
- `API Token` 输入框默认不回填完整值，只作为“新的 token”输入位。
- 保存语义明确：
  - `API Base URL` 变更后可单独保存。
  - `API Token` 为空表示保留现有 token，不代表清空。
  - `API Token` 填入新值才会替换旧值。
- 需提供 `Reset` 与 `Save` 两个操作，避免用户误判编辑是否生效。

## UI 表现

- tab 文案全部为英文，视觉层级与现有导航一致。
- `Overview` 顶部出现一个紧凑的 `Connection` 区块。
- 区块内应展示当前 token 状态，但不默认展示完整 token。
- token 输入框旁应有辅助文案，明确说明空值会保留当前 token。
- `API Base URL` 输入框保留推荐格式提示，推荐形态为 `https://api.openai.com/v1`；提示只帮助用户理解格式，不做冗长说明。
- 保存按钮应在无改动或 base URL 为空时禁用。

## 日志与诊断

- 连接编辑本身不应把完整 token 写入前端日志、浏览器控制台或错误提示。
- 若保存失败，错误信息应只返回安全摘要。
- 后端更新接口必须支持“空 token 保留旧值”的语义，避免 UI 误操作导致凭据丢失。

## 测试与验收

- 账号详情抽屉中 tab 文案统一为英文。
- 直连账号的连接编辑区只出现在 `Overview`，不会出现在 `Playground` 或 `Diagnostics`。
- 空 token 保存不会清除已有凭据。
- base URL 和 token 修改后，详情抽屉能刷新为最新状态。
- token 相关展示不会要求用户看到完整明文。

## 真实容器测试要求

- 使用**新启动的 v0.1.7 容器**验证，不复用、不改动旧版本正在运行的容器。
- 使用隔离的数据目录或只读复制出来的数据副本，保证测试中修改的账号不会污染原实例。
- 在容器里打开一个直连账号详情抽屉，确认 tab 文案为 `Overview / Playground / Diagnostics`，且 `Connection` 区块只出现在 `Overview`。
- 在同一容器里验证 `API Base URL` 修改后能保存并刷新显示。
- 在同一容器里验证 `API Token` 为空时不会清除旧 token，填入新 token 才会替换。
- 验证 UI 不会把完整 token 明文暴露到页面、日志或错误提示中。
- 验证完成后删除测试容器和临时数据目录，不留下可复用的脏状态。

## 已决策记录

- 已确定连接编辑区应放在 `Overview` 顶部，而不是诊断页。
- 已确定 token 默认不回填完整值，采用“当前状态 + 新 token”双轨表达。
- 已确定不提供单独的 `Reveal token` 动作，避免把完整凭据直接暴露到详情抽屉里。
- 已决策：连接编辑区需要显示 base URL 推荐格式提示，采用轻量 placeholder / helper 文案，不引入长说明。

## 后续非阻塞项

- v0.1.7 当前产品口径采用保存后刷新账号详情数据，用于确认保存结果和 masked token，不把保存动作等同于连接成功。
- 保存成功后自动触发完整账号健康刷新已移入 `spec/draft/10-v0.1.7-deferred-followups.md`，不进入 v0.1.7 阻塞范围。
