# v0.1.4 Spec: CPA Runtime Refresh Convergence

Status: released

Release date: 2026-04-30

## Goal

Make CPA-backed accounts recover cleanly after Device Code login in the single-container runtime, without confusing CPA runtime indexing delay with user credential failure.

## User Impact

- A newly added Codex CPA account should not immediately appear broken just because the embedded CPA runtime has not indexed the auth file yet.
- Model discovery, Codex quota refresh, and ChatGPT subscription refresh should use one consistent CPA runtime resolution path.
- The UI should distinguish temporary CPA runtime pending states from real login failures.

## CPA Runtime Resolution

CPA account refresh follows this sequence:

1. Confirm the local auth file exists at `/app/data/cpa-auth/<accountKey>.json`.
2. Wait for CPA management `/v0/management/auth-files` to expose an `auth_index` for that account.
3. Run model, quota, and subscription refreshes only after the runtime route is resolved.

Auth-file matching accepts multiple CPA runtime shapes:

- Direct `id`.
- Direct `name`.
- A derived `provider-email-plan` key.

This reduces false negatives when CPA runtime versions differ in their auth-files response schema.

## Refresh Semantics

- First successful Device Code login triggers an immediate forced refresh.
- If the local auth file exists but `auth_index` is not visible yet, the account is marked `runtime_pending / auth_index_pending`.
- Background health checks continue compensating after that pending state.
- Manual refresh, scheduled health checks, Codex quota refresh, and subscription refresh share the same backend `RefreshAccount` path.
- Model refresh failure must not clear an existing CPA credential error unless credential-related runtime resolution has actually succeeded.
- Codex subscription metadata should prefer the local auth-file JWT when CPA metadata is temporarily unavailable.

## UI Semantics

- CPA credential status supports `runtime_pending`.
- CPA credential status supports `runtime_error`.
- `auth_index_pending` is presented as “CPA runtime has not loaded this credential yet”, not as “the user must log in again”.

## Cleanup

- Remove older `DiscoverModels`, `RefreshCodexQuota`, and `RefreshCodexSubscription` wrapper semantics in favor of `RefreshAccount`.
- Remove obsolete `findAuthIndex` and `auth_index_missing` semantics.
- Keep model discovery logic centralized so manual refresh and scheduled checks do not maintain separate `/models` parsers.
