# v0.2.0 规格整理

状态：审计问题已确认，修复方案待实现。

本文沉淀 v0.1.9 真实容器中发现的 CPA auth JSON 批量导入失败问题。该问题会在“删除已有 CPA 账号后立即重新批量导入”时放大，导致预检全部显示 `created`，但正式导入结果只有部分成功，其余文件显示 `failed / not_applicable`。

本文同时沉淀一套通用可审计性要求，用来解决 Lune 运行在 Docker 容器中时“难审计、难复现、失败原因短暂存在、现场证据蒸发”的系统性问题。

## 目标

v0.2.0 必须修复 CPA auth JSON 批量导入在账号删除、CPA runtime reload、异步健康刷新和 DB 写入交错时出现的部分失败问题。

本版本还必须提升导入失败的可审计性：单项失败不得只在当次 HTTP 响应中短暂出现。导入批次、单项状态、错误码、错误摘要和底层安全错误必须能被后续审计恢复，避免再次出现“UI 显示失败但日志/DB 无法还原真实错因”的情况。

v0.2.0 还必须建立跨功能通用的审计基础能力：关键状态变更要有操作事件、阶段错误、关联 ID、只读 debug 输出和隔离复现脚本。后续版本 spec 在设计新功能或修改运行时行为时，必须同步写清可审计性要求。

## 文档结构

- `01-cpa-auth-json-reimport-pool-member-failure.md`：问题详情、审计结果、根因判断、解决思路和测试矩阵。
- `02-general-auditability.md`：通用可审计性体系，覆盖操作事件、阶段错误、关联 ID、只读 debug、隔离复现脚本、审计包和后续 spec 要求。
- `99-acceptance-matrix.md`：本范围的验收矩阵。
