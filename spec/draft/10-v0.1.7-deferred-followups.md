# v0.1.7 延后后续项

状态：draft

本文件收纳已经从 `spec/v0.1.7` 明确移出的后续项。这些事项不进入 v0.1.7 发布阻塞范围；后续版本如需纳入，必须重新评估产品边界、安全风险、实现成本和验收矩阵。

## 直连账号健康刷新

延后项：保存直连账号 `API Base URL` 或 `API Token` 后，自动触发完整账号健康刷新。

延后原因：

- 保存配置和检查可用性是两个不同动作，自动刷新会让用户误以为保存成功等同于连接成功。
- 健康刷新可能触发上游请求成本、限流或额外失败噪音。
- v0.1.7 已采用保存后刷新账号详情数据的最小闭环，用于确认配置保存结果和 masked token 状态。

后续进入正式规格前，需要明确自动刷新触发条件、失败反馈、上游请求成本和与 `Playground` 的分工。

## 直连轻量连接测试

延后项：在直连账号 `Connection` 区块增加轻量 `GET /models` 测试入口。

延后原因：

- `GET /models` 只能验证 base URL 与 token 是否能列模型，不等同于聊天补全可用。
- v0.1.7 已确认账号级直测统一使用 `Playground`，避免新增入口分散排障心智。

后续如需进入正式规格，需要明确该入口只做模型列表探测，不改写普通路由状态，也不替代 `Playground`。

## Pool Token Reveal 状态清理

延后项：Pool token 替换成功后自动收起当前 reveal 状态。

延后原因：

- 这是交互偏好，不影响 v0.1.7 的凭据替换安全边界。
- v0.1.7 的阻塞要求是替换成功后 masked 值和更新时间刷新，且不能错误切换 reveal 状态。

后续如需调整，需要单独定义替换成功后的 reveal 生命周期和用户反馈规则。

## 完整 Runtime Diagnostics API

延后项：提供完整系统级 runtime diagnostics API，展示容器静态 env、PID1、`lune up` 子进程 effective env、embedded CPA 子进程状态等细节。

延后原因：

- v0.1.7 只需要最小 effective runtime state 数据源，用于支持 Settings 中 `Provider pinning: enabled / disabled / unknown`。
- 展示底层容器与进程细节会扩大安全审计和 UI 解释成本。

后续如需进入正式规格，需要定义字段脱敏、权限边界、外部 CPA 与 embedded CPA 的差异展示，以及哪些信息允许进入 UI、日志和 API 响应。

## 更细 Quota State

延后项：新增更细的 quota state，例如 `limited`。

延后原因：

- 新状态会影响类型定义、数据库迁移、路由条件、UI 优先级和文案。
- v0.1.7 采用保守闭环：复用现有 `blocked` / `error` 等状态，并额外记录 quota / rate-limit evidence。

后续如需新增状态，需要同步定义状态机、降级规则、旧数据迁移和前后端兼容策略。

## 更接近真实 Codex Runtime 的端到端 429 场景

延后项：补充更接近真实 Codex runtime 的专用 fake CPA 容器端到端场景。

延后原因：

- v0.1.7 必须完成可重复的 mock upstream / fake CPA 验收，覆盖 Codex `429` 归类关键路径。
- 更接近真实 runtime 的端到端场景可提升置信度，但不应消耗真实账号额度，也不应阻塞当前最小可重复矩阵。

后续如需进入正式规格，需要定义专用 fake CPA 镜像或测试 harness、固定响应 fixture、运行命令、数据隔离和容器清理要求。

## Auth JSON 批量或目录导入

延后项：

- 批量导入多个 CPA auth JSON。
- 从旧 Lune 数据目录扫描并导入凭据。

延后原因：

- v0.1.7 首版只支持单文件 JSON 导入，安全边界更清晰。
- 批量和目录扫描会显著扩大路径过滤、重复账号处理、回滚、日志脱敏和用户确认成本。

后续如需进入正式规格，必须先完成单文件导入的安全边界、回滚语义和容器验收，再设计批量确认、冲突处理和审计日志。
