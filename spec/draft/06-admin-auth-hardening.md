# 06. 管理端鉴权收紧

状态：draft

## 背景

v0.1.6 暂不取消 private IP 默认免 admin token 的现有行为，但该行为存在后续需要收紧的安全风险。

private IP 不等同于可信本机来源。以下部署形态都可能让管理端被非预期调用方访问：

- 内网部署。
- Docker bridge。
- 反向代理。
- 用户把端口绑定到 `0.0.0.0`。
- 同一内网或同一宿主机上的其他服务。

## 风险

如果管理端暴露在内网或 `0.0.0.0`，仅凭 private IP 绕过 admin token 可能导致管理 API 被未授权访问。

## 后续方向

- 默认所有非 loopback 管理请求都要求 admin token。
- 如果继续支持 trusted proxy，必须显式配置可信代理或可信 CIDR。
- 文档必须说明把管理端暴露到公网或内网时的鉴权要求。
- 反向代理场景下只信任明确配置的代理头，不能默认信任所有 `X-Forwarded-For`。

## 待决问题

- 是否保留 loopback 免 token。
- trusted proxy 配置使用环境变量、配置文件还是 UI 设置。
- 现有用户从旧行为迁移到新行为时是否需要兼容开关。
- 收紧后是否需要在诊断页提示当前管理端鉴权模式。
