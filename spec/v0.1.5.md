# v0.1.5 Spec: Embedded CPA Reload Recovery

Status: released

Release date: 2026-04-30

## Goal

Recover from embedded CPA runtime auth-file indexing stalls after a Codex CPA account is added in the Docker single-container deployment.

## User Impact

- Adding a Codex CPA account should not remain stuck in quota or subscription pending state when the auth file exists locally but CPA management does not expose the account.
- Lune should use a controlled embedded CPA restart as a last-resort recovery path.
- The UI should describe short-lived synchronization delay as backend catch-up, not as a user-side auth error.

## Runtime Reload Flow

When `RefreshAccount` waits for `auth_index` and times out:

1. Confirm the expected local auth file exists in `/app/data/cpa-auth`.
2. If Lune is running with embedded CPA reload signaling enabled, write a reload request to `/app/data/tmp/cpa-reload.signal`.
3. The Docker entrypoint watches that signal file.
4. The entrypoint stops the current CPA child process by PID.
5. The entrypoint starts a fresh CPA child process.
6. Lune waits again for `/v0/management/auth-files` to expose the account.
7. Refresh continues once the runtime indexes the credential.

This fallback is intended for the embedded CPA runtime. External CPA deployments must not be treated as locally restartable by default.

## Process Management Requirements

- The entrypoint owns the embedded CPA child process PID.
- A reload must not leave the old CPA process running.
- The reload watcher should be tied to the Lune container lifecycle and stop with the main process.
- Reload signaling should use the gateway tmp directory so it remains inside the container data boundary.

## UI Semantics

- Missing Codex quota should render with a stable pending quota UI.
- Account cards and account detail should share the same pending quota display.
- Manual refresh pending toast should communicate that Lune is syncing and will fill data later.
- The UI should avoid exposing internal CPA `auth_index` details as user-facing error copy.

## Validation

- `go test ./...`
- `npm run build` in `web/`
- `git diff --check`
- `sh -n docker/entrypoint.sh`
- Docker build succeeds.
- In a copied `/app/data` test container, adding an auth file triggers reload signaling, restarts CPA, and allows auth-files scanning to recover.
